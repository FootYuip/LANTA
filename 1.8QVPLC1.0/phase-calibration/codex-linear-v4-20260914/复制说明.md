# 四项输入：线性输出增益版 v4

适用基线：你截图里正在使用的多参数版 v2。无需安装未使用的 v3。本目录不含导入脚本，原镜像、v2、v3均未修改。

## 只粘贴三个文件的全部内容

1. 在 Application 下新增普通全局变量列表 GVL_PhaseCalSimple。将“复制代码/GVL_PhaseCalSimple.declaration.txt”全部内容粘贴到声明区。
2. 打开已有程序 PRG_PhaseCalibration，将“复制代码/PRG_PhaseCalibration.declaration.txt”全部内容替换上方声明区。
3. 将“复制代码/PRG_PhaseCalibration.implementation.txt”全部内容替换下方实现区。

不是追加，是整区替换。声明文件包含 PROGRAM 标题，不重复添加。实现文件不含 END_PROGRAM，不把完整 .st 文件粘贴进实现区。

旧 GVL_PhaseCal、FB_PhaseTriangle、FB_PhaseFit、READ_485、SecurityCheck 保留，不需要粘贴；不改变任务调用，不重复调用 PRG_PhaseCalibration。

## 日常只打开 GVL_PhaseCalSimple

只填写四项：

- lrBeamWidthDeg：方位和俯仰共用的半功率波束全宽，单位°。
- lrAzGain：接收机当前方位增益，线性倍数。
- lrElGain：接收机当前俯仰增益，线性倍数。
- lrPhaseDeg：接收机当前旋转角，单位°。

按你截图的数值，可填写1、60、60、247，前提是它们确实为当前接收机的实际设置。这里60就是60倍，不是60 dB。零增益不允许，增益必须满足内部范围。

操作命令：xStart、xAbort、xReset。开始需FALSE→TRUE，随后写回FALSE；故障且空闲时先确保xStart=FALSE，再将xReset写TRUE然后FALSE。普通写值，不强制。以后不要从旧GVL_PhaseCal的命令启动，它们由新入口统一写入。

结果只读：xResultValid、lrNewPhaseDeg、lrNewAzGain、lrNewElGain、lrOrthErrorDeg；wsMessage显示原因。只有xResultValid=TRUE才使用三个建议值，无效时面板建议值为0，不能把0写给接收机。

## 已固定的关系

输入电压已经包含当前增益。校相拟合前：Ua归一化=Ua上报/方位当前增益，Ue归一化=Ue上报/俯仰当前增益。

使用归一化电压估计公共旋转及正交度；根据拟合轴灵敏度计算对应新相位下的增益建议。线性新增益=当前增益×目标斜率/预计当前增益下的输出斜率，不进行log或dB转换。

例如相位已正确，当前增益1、规定拉偏的电压变化0.25 V，则建议增益4。若当前增益3、相同拉偏的变化0.75 V，建议仍为4。零点采用拟合截距消除，不把绝对电压当成拉偏变化量。

增益单位固定线性、作用顺序固定为旋转后独立放大；不需要你再选择。程序每次开始锁存这两个固定值，旧GVL中的iGainUnit/iGainOrder被覆盖为0/2。

投影继续采用实际机械角及中心俯仰cos换算。目标固定0.2倍波束全宽对应1 V。只给接收机手动设置建议，不写接收机，也不修改原自跟踪电压链。

## 保留的设备内部限制

本版没有擅自放大机械允许范围或凭空填写加速度。原GVL保留为设备调试区。截图的最大偏置0.1°和最大加速度0仍会使当前1°波束、约35.9°俯仰的快速轨迹拒绝启动：需求是方位约0.2468°、俯仰0.2°、速度约0.421°/s、加速度约1.178°/s²。

这两项必须按实际设备完成一次内部配置；精简输入不等于取消运动限制。相位方向沿用原GVL（截图为1），不重新选择。原增益范围0.01～100按线性倍数继续使用，需与接收机实际范围一致。

正常规划仍5.7 s，新帧不足、到位慢仍判无效。本版不承诺修改后现有零加速度设置即可启动，也不把参数填写错误当作拟合失败；中文提示会说明偏置超限或速度/加速度配置问题。
